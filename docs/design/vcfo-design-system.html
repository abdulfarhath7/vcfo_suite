VCFO Suite

Incorporation and compliance for Indian companies, run by SBC for its clients. One blue for action, navy ink, one orange that means "this needs you", four status colours that always come with a word.

Everything on this page is drawn from the tokens in docs/design/design-tokens.json. Switch the theme above; every swatch, control and screen follows.

Content

Five people use the product: the lead (an SBC associate who runs a client's incorporation), the manager, the firm admin, the super admin, and the client (a founder, often on a phone). The sample data throughout is Northwind Analytics India Pvt Ltd and its lead, Arjun Mehta.

  • Plain English. Say what happened: "Waiting for Northwind", "Due 24 Oct", "11 of 14 steps done". No jargon, no "Submit", no exclamation marks, no emoji.
  • Sentence case for titles, buttons, chips and labels. Table heads and section titles are set uppercase by the label style; write them in sentence case.
  • Buttons are verbs with their object: "Approve ₹9,05,178", "Email manager", "Open incorporation". Two words where possible, never a wrapped label.
  • Dates are real dates, D Mon ("24 Oct", "Wed 21 Oct 2026"); times as "10:42 am". Never "in 5 days" for a statutory deadline.
  • Money carries the rupee sign and Indian grouping (₹9,05,178) in tabular figures, right-aligned in tables. Compact (₹24.6 L) only on dense overview tiles.
  • Identifiers (CIN, PAN, DIN, GSTIN, file names) are set in the mono face. Nothing else is.
  • Status is a word. A colour never carries meaning alone.

Foundations

Colour

surface is the page, a cool off-white; cards are surface-raised inside a line hairline; wells and table heads are surface-sunken. Text is ink, a navy, never black; secondary text ink-muted; ink-faint only for placeholders, disabled and locked steps.

brand is the one action colour: primary buttons, links, the active nav item, selection, progress, the current step. It is text-safe on every surface in both themes, so the same token is a fill, a link and 11px text. brand-soft is a selected row or the active nav ground.

highlight is the one orange. It marks what needs the reader: the overdue figure in the greeting card, a nudge due, the "you" side of an owner chip. One orange moment per screen region. It is never a button and never page atmosphere.

positive, warning, danger and info each have a -soft ground. Warning is amber, twenty degrees from the orange highlight, so "due soon" and "needs you" never look alike. Info is teal, so a note never looks like a button.

Type

Public Sans for everything, weights 400, 500 and 600. There is no 700; emphasis comes from size and colour. IBM Plex Mono for identifiers. The scale runs 11, 12, 13, 15, 20, 22, 28px.

Shape

Radii 6, 8, 10, 12. Chips and avatars are rounded rectangles; pills survive only as toggle knobs and progress rings. Borders before shadows: every card has a hairline and shadow-card only lifts it. shadow-float is for things that really float: menus, popovers, sheets. A 2px rule in ink sits under page heads and table heads.

Weight

The navy sidebar and the greeting card are the only heavy elements. They give the screen its weight so nothing else has to.

Rules

  • Identity never gets a colour. A company, a person, a tag and a nav item are all neutral; only state is coloured.
  • Status chips are soft: tinted ground, text-safe colour, a word. No solid status fills.
  • Buttons in one row share one height; buttons or chips in one column share one width (84px, 88px). Labels never wrap.
  • One primary button and one orange moment per screen region.
  • Rows inside a card are hairline-separated. No cards inside cards.
  • No gradients, no coloured left borders, no blur, no circles except toggles and rings.
  • Hover goes one step darker or to a surface-sunken tint. Disabled is 45% opacity, never a different colour. Motion is 150ms ease on hover and toggles only.
  • Every interactive element gets the 2px focus-ring outline, offset 2px; it holds 3:1 on every surface including the navy sidebar.

Colour tokens

Light and dark are two values of one name. Every text token holds 4.5:1 on the grounds its note names, in both themes; the 52-pair check lives in scripts/design-tokens-check.mjs.

Charts

Six hues in a fixed order, assigned in sequence and never cycled. The set passes the colour-vision checks in both themes. Aqua and yellow sit below 3:1 on white, so light-mode charts that use them carry direct labels or a table view. A series that means good or bad wears the status tokens, never a data slot. Chart text is ink and ink-muted, never the series colour.

Build a dashboard from this system

This page is the brief. A session asked for a manager, admin or super admin screen reads it and builds the screen from the parts above, without a separate spec.

Order of sections

The screen answers questions in reading order: what needs me, what is late, what is coming, who is waiting, then the long lists. The headline numbers go in the greeting card as stats and never again as a band of tiles under it. The side rail holds the health donut and the waiting list.

Rows and lists

A row inside a section is flex items-center gap-2.5 min-h-row border-t border-line first:border-0: a neutral 26px tile with initials, the name at 13px/500, meta at 11px ink-muted under it, a chip at the column width, an optional 28px secondary button. More than eight rows: a DashDataTable or a link to the full page. A list with nothing in it says what will appear there.

Before calling it done

  • Only tokens on this page; rg "#[0-9a-f]{6}|oklch\([0-9]|accent-(amber|rose|violet|emerald|sky|teal|pink|cyan|lime)|border-l-|rounded-full px-|font-extrabold" over the new files returns nothing.
  • npm run typecheck green, npx eslint --quiet clean, npm run test passing.
  • Screenshots in light and dark at 1440px and 375px look like the two screens above.
  • One primary button and one orange moment per region; every status has a word; nothing identity-coloured.

Never

Identity colourA different hue per company, person, tag or nav item. Everything that is not a state is neutral.
Solid status fillsWhite text on a green, orange or grey block. Status is a soft ground, a text-safe colour and a word.
Orange buttonsThe highlight marks what needs the reader. It never sits beside a blue button as a second action colour.
Gradients and blurNo gradient on a product surface, no frosted bars, no hero skins. Flat tokens only.
Coloured left bordersA KPI card carries a 3px top edge in its tone. Notices use a soft ground inside a hairline.
Cards inside cardsRows inside a panel are hairline-separated. One raised surface per panel.
Pills and circlesChips, avatars and tiles are rounded rectangles. Only toggle knobs and progress rings are round.
Zig-zag columnsChips and buttons in a column share one width and centred labels. Labels never wrap.
Weight 700 and 800Public Sans stops at 600. Emphasis is size and colour.
