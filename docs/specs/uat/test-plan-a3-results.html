1How to use this plan

  1. Do the tests in ID sequence. Each test has a day on the schedule (right).
  2. Tick each step box when the step is done and correct.
  3. If a step fails, write a defect on sheet 4. Write the defect ID in the test row. Continue with the next step if you can.
  4. Tick the role boxes when each role saw the correct result.
  5. Tick "Done" only when all steps and all roles pass. Write your initials and the date.

Two tracks

Track AThe real client project. It moves at the speed of the real client.
Track BA sandbox project with test data and a past CIN date. It lets you test post-incorporation, registrations and compliance on schedule.

3Daily loop: test and build

09:30SmokeEach tester signs in and opens their sidebar pages on the new build.
10:00TestDo the tests of the day in ID sequence. Tick each step.
13:30TriageRead the new defects. Set severity and owner. Give S1 and S2 to Claude.
14:00BuildClaude fixes on a branch. Each fix gets a test. npm run check passes.
18:30DeployMerge, apply new migrations, deploy. Write the build tag on the daily log.
09:30+1RetestDo the failed steps again on the new build. Close or reopen the defect.

Severity

S1Stops the workflow, loses data or shows data of a different client.Fix the same day
S2Wrong result. A workaround is possible.Fix in 2 days
S3Text, layout or colour problem.Fix after D10

4Day 0 checklist · Mon 9 Nov

Do the items in sequence. Stop if an item fails. The data delete cannot be undone.

  1. Make an RDS snapshot. Wait for "available".
  2. Copy the S3 bucket to a backup prefix.
  3. Write down the deployed image tag (for rollback).
  4. Delete all data rows. Keep the super_admin login.
  5. Delete all S3 objects of the old data.
  6. Apply migrations 0035 to 0049 on RDS.
  7. Set CREDENTIALS_ENCRYPTION_KEY on App Runner.
  8. Set ASK_VCFO_ENABLED=true.
  9. Make sure SES is out of sandbox mode.
  10. Check the six WhatsApp templates. Set WHATSAPP_ENABLED only if approved.
  11. Run npm run check on main. It must pass.
  12. Deploy main. Status must be SUCCEEDED.
  13. Read the App Runner logs for 10 minutes. No errors.
  14. Create the staff logins (T-02).

Give Claude each defect with

  1. Test ID and step number (for example T-07 step 2)
  2. Role and login email
  3. Page URL
  4. What you did, in steps
  5. What you expected
  6. What happened
  7. Screenshot
